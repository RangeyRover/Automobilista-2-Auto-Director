# Implementation Plan: Cascade Sweep Fix

**Branch**: `feature/2-cascade-sweep-fix` | **Date**: 2026-05-04 | **Spec**: [spec.md](../spec.md)
**Input**: Feature specification from `.specify/features/2-cascade-sweep-fix/spec.md`

## Summary

The cascade sweep fails because of a **timing defect** in `calculate_scores()`. Sweep activation (`_sweep_active = True`) happens inside the per-participant `_calculate_sequence_bonus()` loop, but sweep target selection runs *before* that loop. On the tick P1 finishes, the target selection sees `_sweep_active == False` and skips. On the *next* tick, target selection runs but the participants dict iteration order may not process P1 first, causing further issues.

**Fix approach**: Move both sweep activation detection AND target selection into the main `calculate_scores()` method as a **two-pass architecture** — a pre-scan pass that detects finishers and selects the sweep target, followed by the existing per-participant scoring pass that simply reads the pre-computed target.

## Root Cause Analysis

### The Bug: One-Tick-Late Sweep Activation

```
calculate_scores() execution order:
  1. Sweep Target Selection ← checks _sweep_active (still False on first finish tick)
  2. Per-participant loop:
     2a. _calculate_sequence_bonus(P1) ← sets _sweep_active = True ← TOO LATE
     2b. _calculate_sequence_bonus(P2) ← _sweep_target_name is None → returns 0
     2c. ...
```

On the next tick, step 1 sees `_sweep_active == True` and tries to select a target. But it uses `time.time()` for dwell tracking, which is unreliable in replay playback (replays can be paused, fast-forwarded, or run at variable speed).

### Secondary Issue: `time.time()` in Dwell Logic

Using wall-clock `time.time()` for the dwell period is fragile. In a replay, the user can pause for 30 minutes and the dwell will have long expired. The dwell should be measured in **scoring ticks** (number of calls to `calculate_scores`), not real seconds.

## Proposed Architecture: Two-Pass Scoring

### Pass 1: Pre-Scan (new method `_pre_scan_sweep`)
1. Iterate all participants once
2. For any participant with `current_lap > laps_in_event`: register them as finished
3. If P1 is among the newly finished: set `_sweep_active = True`
4. Select sweep target: highest `race_position` driver who is `is_active` and NOT in `finished_participants` (excluding those within dwell window)
5. Store result in `self._sweep_target_name`

### Pass 2: Per-Participant Scoring (existing loop, simplified)
- `_calculate_sequence_bonus` becomes a pure reader:
  - If `name == self._sweep_target_name` → return 5000.0
  - If final lap leader bonus conditions → return 10000.0
  - Else → return 0.0

### Dwell Tracking: Tick-Based
Replace `time.time()` with a tick counter. Each call to `calculate_scores` increments `_sweep_tick_count`. When a driver finishes, record the tick number. Dwell is measured as `current_tick - finish_tick <= dwell_ticks`. The GUI's `sweep_dwell_time` (seconds) is converted to ticks via `dwell_ticks = sweep_dwell_time / (TICK_MS / 1000)`.
