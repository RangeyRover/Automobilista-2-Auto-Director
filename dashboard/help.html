AMS2 Auto Director V4.0 Guide

Welcome to the AMS2 Auto Director! This application uses an intelligent scoring engine to evaluate the live telemetry of Automobilista 2, automatically switching your game's broadcast cameras to focus on the most interesting action on the track.

It also features a robust local Websocket server that provides highly accurate, zero-latency HTML/CSS web overlays directly to OBS Studio or your browser.

1. Scoring Method Summary

The Auto Director evaluates every active car 60 times a second and calculates a Composite Interest Score. The camera always focuses on the highest-scoring driver. The scoring factors are:

  • Close Racing Bonus: The core driver of the director. The smaller the gap to the car ahead, the higher the score. Caps at the defined 'Max Gap'.
  • Closing Speed Bonus: Additive points based on how fast a car is catching the car ahead.
  • Cars Ahead Bonus: Multiplier based on the number of cars visible within 250m ahead. The race leader receives a much higher multiplier for navigating traffic.
  • Race Position Bonus: A linear decay bonus (e.g., P1 gets the most, P32 gets the least) ensuring the camera prefers front-runners when action is equal elsewhere.
  • Speed & Pit Penalties: Cars that are stopped, crashing, or in the pit lane receive massive negative score penalties to pull the camera away from boring stationary action.
  • Leader Final Lap Sequence: Automatically triggers a massive +10,000 point bonus to lock the camera onto the race leader for the final half-lap of the race, ensuring the checkered flag is captured.
Replay Mode Modifications:

If you load a Replay Timeline Log (gathered via the Replay Logger in the Web Overlays), the scoring engine fundamentally shifts to predictive scoring.

It reads ahead in the timeline log. When an Accident or Overtake is about to happen, it injects a massive bonus score into the involved drivers exactly X seconds before the event occurs (using the Event Pre-Off setting). This guarantees the camera switches to the driver just in time to watch the crash or overtake happen on the replay.

2. Auto Director GUI Controls

The main Python GUI contains a live scoring table and a tuning panel at the bottom. These parameters can be changed mid-race to influence what the AI director cares about.

Core Controls

  • Toggle Director: Turns the automated AI switching ON or OFF.
    Global Hotkey: Ctrl+Space can be pressed anywhere (even while in-game) to instantly pause or resume the Auto Director. 1-8 keys can force specific camera angles while paused.
  • Load Replay Log: Opens a file dialog to select a .txt timeline log for predictive Replay mode.
  • Web Overlays: Opens the local dashboard portal in your default web browser.

Tuning Parameters

  • Interval (s): (Default: 3.0) The minimum "Dwell Time". The camera will not switch away from a driver until this many seconds have passed, preventing rapid nauseating camera cuts.
  • Sweep Dwell: (Default: 1.0) Used during the post-race "Cooldown Sweep". When a car crosses the finish line, the camera will hold on them for this many seconds before cascading back to the next highest-placed finishing car.
  • Pos Factor: (Default: 12.0) How strongly the algorithm prefers cars at the front of the pack.
  • Max Gap: (Default: 50.0) The maximum distance in meters between two cars for them to be considered "battling". If cars are further apart than this, they get no Close Racing bonus.
  • Event Pre-Off: (Default: 15.0) In Replay Mode, how many seconds before an overtake/crash the camera should switch to the driver.
  • Event Post-Off: (Default: 10.0) In Replay Mode, how many seconds the camera is forced to stay on the driver after the event concludes.

Data Source Mode

The Mode button toggles between two data source strategies:

  • Hybrid (Default): Uses Shared Memory as the primary data source, supplemented by UDP for additional telemetry. This is the best option when running AMS2 locally (driving or watching replays).
  • UDP Only: Forces all telemetry to come exclusively from UDP packets. Use this when spectating a multiplayer race remotely, where Shared Memory is present but not populated with active participants.
Automated Fallback:

When in Hybrid mode, the system monitors Shared Memory health. If SHM reports no active participants but UDP has valid track and driver data, it will automatically switch to UDP after 5 consecutive ticks (1 second). The status bar shows "Source: UDP (auto)" in this case. If SHM recovers, it automatically reverts to Hybrid.

Team Colours in UDP Mode:

When running in UDP mode, the overlays parse car name and car class data from the UDP Strings packet. If the packet has not yet been received, car_name and car_class fields in the WebSocket telemetry payload will be blank, and overlays will render with default grey team strips until the data arrives.

3. Adding Overlays to OBS Studio

The AMS2 Auto Director runs a local web server to provide zero-latency overlays.

  1. In OBS, go to the Sources dock and click the + button.
  2. Select Browser. Name it something like "F1TV Leaderboard".
  3. In the properties window, check the box for Local file to FALSE (leave it unchecked).
  4. Set the URL to the specific overlay address (e.g., http://localhost:8765/f1tv_overlay.html).
  5. Set the Width and Height to match your canvas (usually 1920x1080).
  6. CRITICAL: Delete all text in the "Custom CSS" box, except for this: body { background-color: rgba(0, 0, 0, 0); margin: 0px auto; overflow: hidden; }. This ensures the background is completely transparent!
  7. Click OK. The overlay will now appear perfectly on top of your gameplay.

4. Web Overlays Guide

These are the tools and overlays available on the Dashboard Portal.

F1TV Leaderboard Overlay

A highly polished, dynamic F1TV-style broadcast graphic that automatically reacts to the game state. Includes live gaps, fastest lap highlighting, and an animated pit lane timer.

F1TV Overlay Control Panel

Because interacting with overlays inside OBS is difficult, we built a dedicated Remote Control Panel. Open it on a second monitor or smartphone. Clicking any toggle instantly triggers a Websocket command that hides/shows elements on your OBS stream with a smooth animation.

F1TV Halo HUD

An exact replica of the modern F1TV Halo Graphic used for onboard shots. Includes dynamic RPM scaling based on the car's max revs, exact speed telemetry, and an ERS deployment radial glow ring.

JSON Configuration Editor

Live-edit JSON config files directly from your browser. Allows you to map exact driver names to specific teams, assign Hex color codes, and assign nationality flags. The Python server hot-reloads these changes instantly mid-race!

Replay Logger & Analyser

A completely browser-based tool that silently monitors your live race. Open the page, set your close battle gap, and click "Start Capture". It automatically tracks overtakes, accidents, close battles, and leader laps. When finished, it exports a `.txt` log perfectly formatted for the Auto Director's Replay mode!

5. JSON Configuration Schemas

For developers or users wanting to manually build configuration files, below are the required JSON structures for the system's files.

mmdash/drivers_teams.json (MM Dash Colours)

Maps specific driver names to team names, custom Hex colours, and optional logos.

{
  "Max Verstappen": {
    "team": "Red Bull Racing",
    "color": "#0600EF",
    "logo": "url_or_path_to_logo.png"
  }
}

team_lookup.json (F1TV Colours)

Assigns a primary team colour to either an entire AMS2 Car Class, or overrides it for a specific driver name.

{
  "Formula Ultimate Gen 2": {
    "name": "Formula Ultimate",
    "color": "#E10600",
    "short": "FU2"
  },
  "Lando Norris": "#FF8700"
}

driver_lookup.json (F1TV Nationalities)

Maps a driver's name to a 2-letter ISO country code. The overlay will dynamically fetch the corresponding flag from a global CDN.

{
  "Charles Leclerc": "mc",
  "Oscar Piastri": "au"
}
